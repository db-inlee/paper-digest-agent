## 문제 정의
PLC 코드 생성에서 프로젝트에 기반한 생성과 외부 검증을 통한 완료 확인을 통해 신뢰성을 높이는 문제를 해결한다.

**기존 방법의 한계**: 기존 시스템은 생성된 코드가 실행될 수 있음을 보여주기 위해 실행하지만, 얼마나 신뢰성 있게 실행되는지를 측정하지 않는다.

## 핵심 기여 (Delta)
### Delta 1: 프로젝트 기반 생성
- **기존**: 기존에는 프로젝트 구조를 고려하지 않고 코드 생성
- **변경**: 프로젝트 트랙에서 에이전트가 프로젝트 구조를 검색하고 관련 모듈을 찾아 기존 변수와 함수 블록을 재사용
- **이유**: 프로젝트 관습을 유지하면서 논리를 편집하여 코드의 일관성과 재사용성을 높인다 

### Delta 2: 다중 소스 검증
- **기존**: 단일 소스 또는 제한된 검증 방법 사용
- **변경**: 명세 검사, 컴파일, 라이브 런타임 검증을 포함한 다중 소스 검증
- **이유**: 다양한 검증 소스를 통해 코드의 신뢰성을 높이고 오류를 줄인다 

### Delta 3: 검증 게이트 반복
- **기존**: 검증 결과에 따른 반복적 수정 과정이 명확하지 않음
- **변경**: 검증 게이트는 제한된 재시도, 편집 무효화, 획득된 주장에 의해 관리
- **이유**: 명확한 검증 기준을 통해 반복적 수정 과정을 체계화하여 효율성을 높인다 

## 방법론
**Project Grounding**
프로젝트 트랙에서 에이전트가 프로젝트 구조를 검색하고 관련 모듈을 찾는다. 기존 변수와 함수 블록을 재사용하고, 확립된 인터페이스를 재정의하지 않으며, 프로젝트 관습을 유지하면서 논리를 편집한다.
- **입력**: 프로젝트 구조, 관련 모듈
- **출력**: 기반이 된 컨텍스트
- **구현 힌트**: GROUND 단계에서 생성이 작동하는 기반이 된 컨텍스트를 출력한다.
- **역할**: novel (Evidence: p.4 §Project Grounding and PLC Skills)

**Multi-Source Verification**
세 가지 종류의 외부 결과를 일급 증거로 취급하여 검증한다: 명세 검사, 컴파일, 라이브 런타임 검증.
- **입력**: 명세, 컴파일 결과, 라이브 런타임 결과
- **출력**: 검증 결과
- **구현 힌트**: 각 결과는 체크리스트 스킬 문서로 인코딩되어 결함을 타겟으로 한다.
- **역할**: novel (Evidence: p.4 §Multi-Source Verification)

**Verification-Gated Iteration**
검증 게이트는 세 가지 불변량에 의해 관리된다: 제한된 재시도, 편집 무효화, 획득된 주장.
- **입력**: 검증 결과
- **출력**: 수정된 구현
- **구현 힌트**: 각 결과는 도구 호출 로그와 교차 검증된 기계 판독 가능한 센티넬로서의 결과를 요구한다.
- **역할**: novel (Evidence: p.5 §Verification-Gated Iteration)
