**주요 우려**: 적응형 환경의 복잡성이 에이전트 학습에 미치는 영향에 대한 충분한 검토가 필요할 수 있다.

## 한 줄 요약
이 논문은 고정된 환경에서의 학습 한계를 극복하기 위해 적응형 환경을 생성하는 Self-Play 기반의 SPADE 프레임워크를 제안한다.

## 문제 정의
기존의 고정된 환경 풀은 학습자가 개선됨에 따라 적응하지 않기 때문에, 에이전트가 이를 소진하면 더 이상 개선되지 않는 문제를 해결하고자 한다.

**기존 방법의 한계**: 기존의 환경 생성기는 고정되어 있어, 에이전트가 환경 공간을 빠르게 소진하게 된다.

## 핵심 기여
- SPADE는 환경 설계를 학습 가능한 역할로 만들어, 에이전트의 학습 경계에 있는 환경을 생성하도록 한다.
- 힌트 기반 후회 보상은 Reasoning Agent의 학습 경계에 있는 환경을 목표로 한다.

## 방법론
### Environment Designer
Python 코드로 실행 가능한 환경을 생성하는 역할을 하며, 힌트 기반의 후회 신호를 통해 강화 학습으로 학습된다.
- **입력**: 환경 메모리, 사전 학습 코퍼스
- **출력**: 실행 가능한 환경, 특권 힌트
- **구현 힌트**: 힌트 기반 후회 신호를 사용하여 환경을 생성

### Reasoning Agent
생성된 환경에서 행동을 학습하며, 힌트가 있는 경우와 없는 경우의 성과 차이를 통해 학습된다.
- **입력**: 실행 가능한 환경, 특권 힌트
- **출력**: 행동 성과
- **구현 힌트**: 힌트가 있는 경우와 없는 경우의 성과 차이를 통해 학습

### Hint-based Regret Reward
Reasoning Agent의 힌트 유무에 따른 성과 차이를 기반으로 Environment Designer에게 보상을 제공하는 메커니즘.
- **입력**: Reasoning Agent의 성과
- **출력**: Environment Designer의 보상
- **구현 힌트**: 힌트 유무에 따른 성과 차이를 기반으로 후회 신호를 계산

- **에이전트 학습 방식**: 다양한 환경에서의 적응력을 높여 에이전트의 성능을 향상시킴

**핵심 혁신:**

루프드 언어 모델(looped language models)이 에이전트 시스템에서의 도구 사용을 개선할 수 있는지 평가한다.

### Looped Transformers

- **출력**: 정제된 예측 시퀀스 {π(1)θ, ..., π(T)θ}
- **구현 힌트**: Fθ(h(t−1))를 사용하여 숨겨진 상태를 갱신

### Adaptive Inference
루프드 Transformer가 학습된 정지 정책이나 사후 기준을 사용하여 동적으로 계산을 할당
- **입력**: 각 토큰의 누적 종료 확률
- **출력**: 선택된 루프 깊이
- **구현 힌트**: 학습된 정지 정책을 사용하여 종료 반복을 선택

### Compositional Tool Use Formalism
도구 호출과 그 종속성에 대한 구조적 예측으로 구성된 공식화
- **입력**: 사용자 요청 x
- **출력**: 구조화된 도구 호출 분포 pθ(ck | x)
- **구현 힌트**: 도구 사용 솔루션을 방향성 비순환 그래프로 표현

### 3. SemaPLC: A Project-Grounded, Verification-Gated Agent Harness for PLC Code Generation ⭐⭐⭐⭐

**PDF**: [다운로드](https://arxiv.org/pdf/2608.18565.pdf)
**GitHub**: [https://github.com/midea-ai/SemaPLC](https://github.com/midea-ai/SemaPLC)
**매칭 키워드**: agent

## 왜 이 논문인가?
총점: 11/15

🎯 점수 상세:
  - 실용성 (Practicality): 4/5
  - 구현 가능성 (Codeability): 3/5
  - 신뢰도 (Signal): 4/5

💡 평가 근거:
이 논문은 PLC 코드 생성의 신뢰성을 높이기 위한 프로젝트 기반 생성과 다중 소스 검증을 제안하고 있으며, 실제 문제 해결 가능성이 높다. 그러나 구현의 복잡성으로 인해 중간 정도의 구현 가능성을 보인다.

**주요 강점**: 프로젝트 기반 생성과 다중 소스 검증을 통해 신뢰성을 향상시키는 접근 방식이 강점이다.
**주요 우려**: 구현 과정에서의 복잡성과 검증 게이트 관리의 명확성이 부족할 수 있다.

## 한 줄 요약
이 논문은 PLC 코드 생성에서 프로젝트 기반 생성과 외부 검증을 통한 신뢰성 향상을 목표로 하는 SemaPLC 프레임워크를 제안한다.

## 문제 정의
PLC 코드 생성에서 프로젝트에 기반한 생성과 외부 검증을 통한 완료 확인을 통해 신뢰성을 높이는 문제를 해결한다.

**기존 방법의 한계**: 기존 시스템은 생성된 코드가 실행될 수 있음을 보여주기 위해 실행하지만, 얼마나 신뢰성 있게 실행되는지를 측정하지 않는다.

## 핵심 기여
- SEMAPLC는 프로젝트에 기반한 생성과 외부 검증을 통해 PLC 코드 생성의 신뢰성을 높인다.
- SEMAPLC는 런타임 검증을 통해 결함을 감지하고 수정하며, 런타임에서 검증된 솔루션을 제공한다.

## 방법론
### Project Grounding
프로젝트 트랙에서 에이전트가 프로젝트 구조를 검색하고 관련 모듈을 찾는다. 기존 변수와 함수 블록을 재사용하고, 확립된 인터페이스를 재정의하지 않으며, 프로젝트 관습을 유지하면서 논리를 편집한다.
- **입력**: 프로젝트 구조, 관련 모듈
- **출력**: 기반이 된 컨텍스트
- **구현 힌트**: GROUND 단계에서 생성이 작동하는 기반이 된 컨텍스트를 출력한다.

### Multi-Source Verification
세 가지 종류의 외부 결과를 일급 증거로 취급하여 검증한다: 명세 검사, 컴파일, 라이브 런타임 검증.
- **입력**: 명세, 컴파일 결과, 라이브 런타임 결과
- **출력**: 검증 결과
- **구현 힌트**: 각 결과는 체크리스트 스킬 문서로 인코딩되어 결함을 타겟으로 한다.

### Verification-Gated Iteration

- **다중 소스 검증**: 다양한 검증 소스를 통해 코드의 신뢰성을 높이고 오류를 줄인다
- **검증 게이트 반복**: 명확한 검증 기준을 통해 반복적 수정 과정을 체계화하여 효율성을 높인다

**핵심 혁신:**

- [기존: 단일 소스 또는 제한된 검증 방법 사용] → [변경: 명세 검사, 컴파일, 라이브 런타임 검증을 포함한 다중 소스 검증]
- [기존: 검증 결과에 따른 반복적 수정 과정이 명확하지 않음] → [변경: 검증 게이트는 제한된 재시도, 편집 무효화, 획득된 주장에 의해 관리]
